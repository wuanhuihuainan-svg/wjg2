# 多参考图绑定与合成首帧

当输入同时包含人物图、场景图、道具图、首尾帧或参考视频时读取。本文件解决“参考越多越容易漂”的问题：每项资产只能承担明确职责，每个视频片段只选择一个主驱动视觉输入。

## 资产登记

为每项资产记录：

- `asset_id`、类型、来源和用户给出的名称；
- 绑定到哪个 `character_id`、`scene_id` 或 `prop_id`；
- `primary_role`：`identity`、`space`、`prop_design`、`pose_state`、`motion`、`style` 之一；
- 可见污染：人物、强背景、文字、水印、其他服装、错误道具；
- 状态：`confirmed`、`pending`、`conflict` 或 `derived`。

同一资产不要同时主导空间和人物身份。场景图里已有的人物不是默认人物资产；人物图里的背景不是默认场景资产。

## 真源优先级

按字段而不是按整张图片决定真源：

| 字段 | 首选真源 | 次选 |
|---|---|---|
| 脸、发型、体型 | 已确认人物资产 | 已确认人物合成首帧 |
| 服装、饰品 | 当前场次人物状态 | 人物资产 |
| 房间布局、门窗家具 | 已确认场景资产/白模 | 已确认合成首帧 |
| 起始姿态、位置、朝向 | 前段稳定尾帧或当前合成首帧 | `start_state` |
| 道具形状 | 道具资产 | 剧本描述 |
| 道具归属、手别、状态 | 连续性账本 | 当前首帧 |
| 动作与对白 | 剧本/音频账本 | 无 |
| 画面风格 | 已确认视觉圣经 | 场景资产 |

发现冲突时只冻结冲突字段，不把整套项目判废。例如人物图服装与当前场次服装不同，只阻止该角色的服装绑定，空间规划仍可继续。

## 常见污染与降级

- 场景图带无关人物：优先生成/选择空场景底图；做不到时把该人物登记为 `embedded_person`，不得同时用其位置或身份约束新角色。
- 人物图背景强烈：先做中性背景人物板或干净裁切；视频节点不要让该背景与场景图竞争。
- 多人物合照：若无法无歧义地拆分角色，必须让用户确认人物映射；不得按左右位置自行长期命名。
- 服装或年龄冲突：以用户确认的当前场次状态为准；其余参考仅保留不冲突的脸部/体型信息。
- 场景比例与人物尺度冲突：先在合成首帧中校正，再把合成首帧作为主驱动。
- 参考数量超过平台上限：按本镜风险最小化附件；未使用资产写入 `unattached_assets`，不宣称已绑定。

## 每段参考输入矩阵

每个片段至少记录：

| 输入 | 职责 | 优先级 | 是否附加 | 冲突处理 |
|---|---|---:|---|---|
| `start_keyframe` | 构图、位置、姿态、场景 | 1 | 是 | 主驱动，不与尾帧并列主驱动 |
| `CHAR-01_REF` | 人物 1 身份 | 2 | 视平台能力 | 只约束脸/发型/体型 |
| `SCENE-01_REF` | 空间锚点 | 2 | 视平台能力 | 与首帧不一致则退回重建首帧 |
| `PROP-01_REF` | 道具设计 | 3 | 仅剧情关键时 | 不控制构图 |

`primary_driver` 必须且只能有一个。若平台要求首帧输入，使用 `start_keyframe`；若平台不支持图像主驱动，仍保留矩阵，并把职责逐项编译成文字。

## 合成首帧步骤

1. 选择干净场景底图，锁定画幅和锚点。
2. 按 `start_state` 放入每位人物，明确屏幕左/右、远近层、朝向、尺度和遮挡关系。
3. 放入剧情关键道具，明确持有者、左右手或承载表面。
4. 对齐主光方向、色温和阴影；不让人物像贴纸漂浮。
5. 输出一张无路线、无标签、无网格、无水印的干净画面作为视频首帧。
6. 另保留带标注的审阅副本；审阅副本不得作为主视频输入。

## 首帧 QC

必须全部通过：

- 人数与角色绑定正确；脸、发型、体型和服装无串用；
- 人物脚底/接触面、尺度、透视和阴影与场景匹配；
- 门窗、家具、通道和三个以上锚点与场景真源一致；
- 道具形状、归属、左右手和状态正确；
- 构图包含动作所需净空，且下一步动作物理可达；
- 没有九宫格边框、路线、长文字、候选编号或无关人物。

任何一项失败，先修首帧，不用视频提示词补救。

## 提示词中的引用方式

不要写“所有参考图一模一样”。改为逐项声明：

`以 start_keyframe 为构图、空间和起始姿态的主参考；CHAR-01_REF 只约束 CHAR-01 的脸、发型和体型；SCENE-01_REF 只校验门、窗、桌与主光方向；动作和对白严格来自脚本。若参考间冲突，以本句字段职责为准。`
